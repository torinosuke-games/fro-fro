# Claude Code向け評価・引継ぎ

## 独立性

追加範囲は `codex-prototypes/snow-battle/` のみ。`codex-prototypes/snowfield-canvas/` と本編のHTML/CSS/JS、保存データ、仕様資料には変更を加えていません。試作は本編のJSを読み込まず、localStorage・IndexedDB・ネットワークAPIに書き込みません。初期化状態は各ページ内のメモリーに保持します。

## 評価してほしいこと

1. 縦持ちで仲間を選び、回復対象まで迷わず決められるか。
2. 問題と選択肢が読みやすく、正解と説明を確認してから行動できるか。
3. 間違い／わからないが行き止まりにならないか。
4. 横持ち・小画面のパネル内スクロール、演出×2、動きを減らす設定の使い勝手。
5. オートONで問題と解説を読めるか。OFF、ヘルプ、非表示タブ、勝敗で正しく停止するか。
6. 静止背景と立ち絵の重なりで雪山らしい奥行きが得られるか。

## 採用時の境界

試作の戦闘モデルをそのまま本編へ置換しないでください。既存 `js/adventure.js` の command → question → explanation → playerAction → enemyAction の流れに、この画面構成を接続するのが基本です。予約の取消・MP・道具消費・戦闘終了判定は本編の処理を正とし、試作から持ち込む二重の状態を作らないでください。

オートは既存のおすすめ作戦を毎ターン選び、ターン終了後に次の問題へ進みます。問答と解答確認は人が操作します。1.5秒の進行タイマーは画面遷移、OFF、非表示、ダイアログで取り消します。正式採用では本編の自動作戦ロジックへ接続してください。

この試作の対象指定、かばう・回復・防御の値、敵行動、命中・攻撃値、12問の形式は試験用です。本編の問題バンク、ふりがな、学年・単元・言語設定、現行テーマ、音量設定、保存・復帰に接続する必要があります。

既存DECISIONSの敵行動予告を出さない方針、説明をヘルプに集約する方針、コマンド件数を進捗表示しない方針、オート操作でも問題は必須とする方針を尊重しています。

勝利・敗北が確定するターンでも「問題表示 → 正解と解説の表示 → 明示的な確認」の前に行動を開始しないことが必要です。背景復帰とダイアログを閉じる際は、同じイベントを二度適用しないようにします。

逃走ボタンは上部の記録・ヘルプの隣に配置しました。確認を挟み、コマンド／ターン終了では即時撤退、問題／解説中では撤退を予約し、明示的な解答確認後に行動せず終了します。行動中は無効です。撤退はオート・タイマー・演出を停止し、学習履歴を残します。試作では必ず成功します。本編の逃走制限・成功率・反撃処理はこの試作に定義していません。`qa/escape-results.json` に検証結果があります。

## 構成

- `index.html`：画面の枠と静的素材。
- `style.css`：縦／横／PC、戦場と仲間カードの固定レイアウト、動きを減らす設定。
- `data.js`：試験用4人と12問。
- `battle.js`：画面遷移、予約、確認待ち、短い演出、履歴。永続保存なし。
- `assets/*-source.png`：生成元。ランタイムで読み込まない。
- `qa/verify.cjs`：Playwright＋Chromiumで再検証。HTTP配信の `BATTLE_URL` と必要なら `FF_BROWSER_PATH` を指定。
- `?qa=1`：検証時のみ状態確認・fixture・イベント完了操作を公開。通常URLでは公開しない。

## 再評価履歴

最初の画面を確認し、HPバーの寸法、小さい縦画面での問題領域、仲間の立ち絵の配置を修正しました。再確認では操作通知が決定ボタンに重なることを見つけ、上部への移動と画面遷移時の消去を追加しました。最終画面は `qa/phone-*.png`、小画面は `qa/small-*.png`。`*-v1.png` は初回の比較記録です。

作戦選択のスクロールを避けるため、タイトル帯を廃止し、TURN・進行表示・記録・ヘルプを一行にしました。作戦見出しと余白を圧縮し、開始時に画面高と作戦パネルの必要な高さから戦場サイズを決めます。回復対象を表示する場合を含め、7画面サイズ×4人で作戦とショートカットの表示範囲を検証しました。`qa/layout-results.json` が結果です。スマホの上部ボタンは高さ32px、上端余白は6pxとし、空いた領域を戦場に戻しています。縦画面では開始時に4人×4種のコマンドの表示高を測定し、最も長い説明でも操作が収まる領域を確保します。残りを戦場へ割り当て、戦闘の各段階や仲間の変更では再計算しません。戦場・仲間カード・立ち絵の配置を固定し、問題・解説・行動履歴はパネル内をスクロールします。画面のサイズや向きの変更、再戦でのみ再計算します。

スマホの操作パネルでは、作戦・問題・解答・行動の繰り返す指示見出しを非表示にしています。非表示見出しへフォーカスせず、問題文や解答状態へ移動します。戦場の計測時は以前の見出し高を確保し、削減した領域を戦場の拡大ではなく出題領域へ割り当てます。図の高さと周囲の余白も調整し、5種類のスマホ画面サイズ×12問の問題文・図・4択が初期表示で見えることを `qa/question-layout-results.json` に記録しています。

実機検証が残っています。とくにiOS Safariの動的ビューポート、OS文字拡大、低価格Androidでの解像度と演出速度を評価してください。模擬CPU測定は実機のFPSを保証するものではありません。
